INCIDENT REPORT - WEB SERVER LOG ANALYSIS

Log: access.log (2614 requests, 15 March 2024, from 08:00 to 12:04)

1. Executive Summary

The server log for 15 March 2024 shows three kinds of attack: brute-force login
attempts, SQL injection and directory traversal. The brute-force attempts went
after the login pages (/login, /admin/login, /api/login and /wp-login.php). The SQL
injection requests went after the search, products, login and api/items pages,
which use the database. The directory traversal requests went after the file pages
(/download, /files, /img, /view) and tried to read files like /etc/passwd,
/etc/shadow and .env. The biggest attackers were 203.0.113.42 (12 failed logins),
51.77.72.9 (6 SQL injection requests) and 88.198.50.20 (7 traversal requests).
Other IPs also matched the rules, and 141.98.10.33 used all three attacks within
four minutes. I rate the incident as HIGH. Most of the bad requests were refused
with 400, 403 or 404, but some got 200 or 500 replies. Also, 203.0.113.42 logged in
successfully at 08:46:00 right after its failed attempts, so that account may have
been taken over.

3. Recommended Actions

Brute Force: limit how many login attempts one IP can make, lock the account for a
while after too many failures, turn on two-factor login, and block the attacking
IPs. Reset the password of the account that 203.0.113.42 logged into at 08:46:00.

SQL Injection: use prepared statements (parameterized queries) instead of putting
user input into SQL text, check all input, and add a web application firewall rule
for these patterns. Look at the requests that got 200 or 500 replies to make sure
no data was leaked or changed.

Directory Traversal: clean up and check every file path before opening it, only
allow files inside one approved folder, reject paths with "../", and run the web
server with as few file permissions as possible.
